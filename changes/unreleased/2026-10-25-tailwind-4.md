- **UI: Upgraded Tailwind CSS to 4.3.3 (Dependabot PR #415, [Issue #305](https://github.com/SteveRodrigue/MCD/issues/305)); card frames now show their 3px border (Fixes #373)**
  - Tailwind now runs through `@tailwindcss/vite`, so `postcss.config.js`, `autoprefixer` and the `postcss-selector-parser` override are gone. The theme stays in `tailwind.config.js`, loaded with `@config`, because tests and the z-index scale depend on it; `@source` limits class scanning to `index.html` and `src/`.
  - Class names follow Tailwind 4: `rounded` is `rounded-sm`, `rounded-sm` is `rounded-xs` (also the directional forms), `shadow-sm` is `shadow-xs`, `outline-none` is `outline-hidden`, `bg-gradient-to-*` is `bg-linear-to-*`, the `!` modifier is a suffix, and `border-[3px]` is `border-comic`. Two defaults Tailwind 4 changed (a gray-200 border colour and a pointer cursor on buttons) are restored in `src/ui/styles/index.css`.
  - Checked by comparing computed styles of about 38 screens (setup, Card Editor, the lab's styles and kits) before and after. What changed on purpose: classes that did nothing in Tailwind 3 but were written for Tailwind 4 now apply (`border-3` on card frames, `shadow-xs`, `backdrop-blur-xs`, `drop-shadow-xs`), so card frames now have the 3px border their code asked for; `leading-*` now wins over the line height of `text-*`; Tailwind's default colour palette is a little different (for example `yellow-300` is brighter); native `<option>` rows lose their default padding.
  - Browsers: Safari 16.4+, Chrome 111+ and Firefox 128+ are now the minimum.

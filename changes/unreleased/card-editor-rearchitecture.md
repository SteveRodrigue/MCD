type: Changed

- **Card Editor re-architecture, Phase 1: supplemental schema purge ([#319](https://github.com/SteveRodrigue/MCD/issues/319), ADR-0083)**
  - Supplemental cards no longer declare values the upstream card data already provides: `traits`, `keywords`, `maxPerPlayer`, `isLandscape`, `restrictedSlots`, `additionalBoostCards`, `attackCost`, `thwartCost`, `victoryPoints` and ability `labels` are removed from the schema and derived by the loader.
  - Printed `Victory X` (including `Victory 0` and negative values) is now parsed into the Victory keyword.
  - Allies with no printed consequential damage icon now take 0 consequential damage (was 1 when upstream omitted the value).
  - Ability resource costs use one typed map (`resourceCost: { energy: 1 }`); `cost.resources` and the untyped numeric `resourceCost` are gone. Enhanced Spider-Sense, One-Two Punch and Get Behind Me! now pay their printed event cost instead of a copied value.
  - Steps declare `target`, `filter` and `distinctFrom` only inside `effectParams`.
  - Event abilities played from hand with no declared cost are now checked against the printed event cost before payment, matching how they are paid.
- **Phase 2: schema-driven parameters**
  - New headless `schema-introspector.ts` turns `.meta()`-annotated Zod schemas into form field descriptors.
  - Every effect primitive now has a strict `effectParams` schema (`EFFECT_PARAM_SCHEMAS`); unknown or wrongly typed parameters are rejected when packs load. All 196 parameterized steps in the 5 packs validate.
  - Gate parameter fields are derived from their schemas instead of hand-written lists.
- **Phase 3: schema-driven Card Editor forms**
  - New `<ZodSchemaForm />` renders any annotated schema (selects, pills, numbers, checkboxes, card filters, card locations, dynamic values) and shows unset optional fields as `+ Add` chips.
  - Effect parameters, trigger filters and ability costs are rendered from their schemas; the 1,365-line hand-written parameter registry is deleted.
  - Card attributes: one chip bar (Play Requirements, Uses / Counters, Attachment Host, Obligation Recipient, Cross-Player Control, Errata) plus read-only upstream badges (traits, keywords incl. Victory X, max per player, consequential damage, restricted slots, dash powers).
  - The redundant Visual Review tab is removed; the inspector has Form Builder and Raw JSON.
  - Number fields accept negative values where the schema allows them; Dynamic Value sources now include `PREVIOUS_EXCESS_DAMAGE` and a target card code.
- **Phase 4: progressive disclosure for abilities and steps**
  - Abilities show only the timing window (and the event trigger for interrupt, response, when-revealed and boost timings); cost, trigger filter, limit, zone, for-each-player and errata are `+ Add` chips until set.
  - Printed `(attack)` / `(thwart)` / `(defense)` labels appear as read-only `AUTO` badges in the ability header.
  - Steps show the effect and its parameters; gate, step ID and uncancelable are `+ Add` chips. Removing a gate also removes its parameters.
- **Phase 6: one set of types, Toughness fixed**
  - Toughness is the keyword and Tough is the status card (RR v1.8, #280): Rhino, Luke Cage and Sandman get their tough status card through the Toughness keyword, without a name alias.
  - Card filters accept every engine keyword (23).
  - The engine uses the supplemental schema's types directly; unused engine-only effect names, cost fields and triggers are removed. Discard, boost-reveal and leaves-play reactions are tracked as missing features (#320, #321, #322).

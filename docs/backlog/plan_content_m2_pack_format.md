# Plan — M2: Pack format, manifest schema, hook API contract and validator

**Status:** Draft for review (2026-10-31). Pure additions plus one type-derivation refactor; no behavior change.
**Parent:** [`plan_content_folder_refactor.md`](plan_content_folder_refactor.md) (Q7, Q10, Q16, Q18, Q27, Q30, Q33).
**Gate:** none (Q6). Depends on M0 (ADR-0092) for the terms; can be written in parallel.

## 1. Goal

Define, in code, what a pack is: the `pack.json` manifest, the validated shape of every pack file, the engine-to-pack hook
contract with its `apiVersion`, and a validator CLI. Nothing loads a pack at runtime yet (that is M3).

## 2. Rules and spec analysis

- No gameplay rule changes. Raw card format stays zzorba/MarvelCDB JSON (Q10); `data/upstream/schema/card_schema.json`
  already constrains card `code` to `^[0-9]{5}[abcdef]?$`.
- Verified existing facts this plan builds on:
  - Zod is `^4.5.4` with native `toJSONSchema`; supplemental schema lives in `src/data/supplemental/schema.ts`, generated by
    `tools/generate-supplemental-schema.ts` into `src/data/supplemental/schema.json` via `npm run schema:generate`.
  - The in-sync gate is a vitest test (`tests/data/supplemental-schema.test.ts` compares disk to generator output).
  - There is **no zod schema** for scenarios or modular sets, only the TS interface `ScenarioDefinition` in
    `src/engine/scenarios/types.ts`. Rhino, Klaw and Ultron `definition.json` share the same keys. `modular-sets.json` is a
    top-level array of 5 `{code, name, description}` entries.
  - Official codes seen in data: `\d{5}`, `\d{5}[a-d]`; 63 official pack codes in `data/upstream/packs.json`, with
    `<code>.json` and `<code>_encounter.json` files.
  - `src/engine/specials/special-registry.ts` (`SpecialAbilityHandler`) and `ScenarioPlugin` (`src/engine/scenarios/types.ts`)
    are today's only code extension points; there is no `apiVersion` anywhere.

## 3. Design

### 3.1 Manifest (`pack.json`)

`{ id, name, kind, origin, apiVersion, version, dependsOn[], source? }`.

- `id`: `^[a-z][a-z0-9-]{2,31}$`.
- `kind`: `core | hero | scenario | campaign | mixed`.
- `origin`: `official-bundled | official-sync | user` (Q27). Official origins are read-only to the editor and loader writes.
- `apiVersion`: integer; the loader (M3) refuses a pack newer than the engine's `PACK_API_VERSION`.
- `dependsOn`: pack IDs, acyclic, each must resolve.

### 3.2 Per-file schemas

| File | Schema |
| --- | --- |
| `cards/*.json` | Reuse the existing card normalisation input type; validate user packs' codes as `<packId>-NNNN` and official as the upstream pattern. |
| `supplemental/*.json` | Existing `SupplementalPackSchema` (unchanged). Cross-check: every key exists in the pack's own or a dependency's cards. |
| `scenarios/<id>/definition.json` | **New** `ScenarioDefinitionSchema`; the TS interface becomes `z.infer<...>` (no duplicate definition). |
| `modular-sets.json` | **New** schema for the array of `{code, name, description}`; codes are snake_case and unique across loaded packs. |
| `decks/*.json` | Schema of the existing prebuilt deck shape. |

### 3.3 Hook API contract (Q16)

A types-only barrel `src/engine/plugin-api/index.ts` exporting `PACK_API_VERSION`, `PackHooks`
(`{ scenarioPlugins?: ScenarioPlugin[]; specialHandlers?: SpecialAbilityHandler[] }`) and re-exports of those two existing
interfaces. It **names** the contract existing code already follows; it adds no registry and no loading. The M5
generated import map (Q33) and the M3 loader both consume it. Rule enforced now: a pack with `origin: user` must not
contain `scripts/` (Q16). The "scripts require an import-map entry" check (Q33) lands with the map in M5.

### 3.4 Reserved IDs (Q18)

`pack:validate` rejects a user pack whose `id` equals an official pack code (read from `data/upstream/packs.json`, or its
pack-level equivalent after M4), ends in `_encounter`, or matches `^\d`; and rejects user card codes that match the official
pattern `^\d{5}[a-f]?$`. Duplicate pack IDs and card codes across a pack set are errors (loader enforces the same rule in M3
using the shared function).

## 4. Simplification & Refactor Check

- **Merge, don't add a generator.** `tools/generate-supplemental-schema.ts` is generalised to emit a list of schemas
  (supplemental, pack manifest, scenario definition, modular sets); `schema:generate` still runs once. No second generator script.
- **Merge the test.** `tests/data/supplemental-schema.test.ts` pattern is parameterised over the same list, so each new
  schema gets the "disk equals generated" assertion without copy-paste.
- **Derive, don't duplicate.** `ScenarioDefinition` and `ScenarioGameSetupOptions` stay as the engine's types, but
  `ScenarioDefinition` is `z.infer` of the new schema. Rhino, Klaw, Ultron definitions are validated against it in the same PR.
- **Reuse, don't add.** `validatePack` follows the `runDocsCheck` / `validateCardInput` shape (pure function returning
  findings, guarded `main`, exit 1 on findings). It calls `validateCardInput`'s schema for supplemental entries.
- **Delete.** The loose placeholder `"$schema": "http://json-schema.org/draft-07/schema#"` in the three `definition.json`
  files is replaced by a real relative schema path (as pack supplemental files do), so editor tooling works.

## 7. Debt Removed

- The scenario shape stops being defined twice (TS interface plus unvalidated JSON).
- Hand-written scenario JSON gets real validation (required by Q7), instead of failing at game setup.
- The placeholder draft-07 `$schema` URLs go away.
- The hook "contract" stops being implicit across `special-registry.ts` and `ScenarioPlugin`.

## 8. UI and Card Editor impact

None at runtime. The Card Supplemental Editor is untouched in M2. Editor tooling benefits from the new JSON schema mappings in VS Code.

## 9. Open decisions

1. **Where the validator lives.** `scripts/` (user-facing CLI, matches `card:validate`) vs `tools/`. **Recommend `scripts/`.**
2. **Reserved-ID source before M4.** Read `data/upstream/packs.json`. After M4 it moves to the Core pack; the predicate takes
   the list as a parameter so only the caller changes. **Recommend the parameterised predicate.**
3. **`apiVersion` semantics.** Integer, loader rejects greater than the engine's, accepts lower until a break is declared.
   **Recommend this** over semver ranges for the first version.
4. **Card schema reuse.** Validate pack `cards/` with the upstream JSON schema plus the user-code rule, rather than a new
   zod card schema. **Recommend reuse**, to honour Q10.

## 10. Done when

All schemas are generated and checked in, the three real scenarios and the modular-set list validate, `plugin-api` compiles
against existing handlers, `npm run pack:validate -- <dir>` works on a temp pack in tests, and the targeted checks above pass.
